Getting started

What is Wingman AI?

An AI assistant for your own Tinder account. It reads your profile and conversations with Google's Gemini models, gives you honest feedback, rewrites bios and prompts, drafts replies in your chosen tone — and never takes an action without your explicit approval.

Quick start (2 minutes)

1
Run the app locally and open http://127.0.0.1:8000 (or use the hosted demo — no connection needed).
2
Get your token from tinder.com — the visual guide shows every click.
3
Paste it into Connect. You'll see “Connected as …” within seconds.
4
Open Profile → Analyze. That's the whole onboarding.

Connecting Tinder & authentication

Wingman uses the same login credential your browser holds for tinder.com (a 36-character token). You copy it yourself and paste it into the app — Wingman never asks for your password, never uses OAuth screens, and never needs your phone number. Full details in the Connect guide.

Using Wingman

Profile analysis

Open Profile → Analyze with AI. Gemini scores your bio, prompts, and photos, explains the reasoning, and produces: 2–3 rewritten bios in different tones, sharper versions of your prompt answers, per-photo feedback with a recommended order, and a list of gaps (like “no full-body shot”).

Conversation analysis & replies

Open Conversations and pick a chat. Choose a tone (casual / funny / flirty / confident / balanced) and press Analyze. You get a read on tone and engagement, topics worth pulling on, issues (interview-mode, fading), a concrete next move, and three drafts you can edit inline.

Messaging — review then send

Every message is a two-step action: AI drafts → you edit → you press Send → you confirm. There is no auto-send path in the product; the AI layer physically cannot send (see architecture below). The demo instance shows the full flow with sending disabled.

Match management & insights

The Conversations list flags chats waiting on you and new matches you haven't messaged. Insights computes totals, response balance, and shared-interest overlaps from your real history.

Technical

Architecture

User ↓ Frontend (vanilla JS + CSS — web/) ↓ JSON over HTTP Backend (FastAPI — app.py, server/) ├── routes.py API surface + session handling ├── session.py token in memory only, HttpOnly cookie, 2h idle TTL ├── errors.py every failure → friendly message (no stack traces to users) ├── tinder_api.py the ONLY module that talks to Tinder ├── coach.py AI orchestration (prompts, validation, no network rights) └── gemini.py the ONLY module that talks to Google Cloud ↓ ↓ Tinder API Vertex AI (Gemini) (reads + gated writes) (text + photo vision)

MCP architecture

Wingman grew out of an MCP (Model Context Protocol) prototype: the Tinder tools were originally exposed as MCP tools for an LLM client. In this product the same clean tool boundary remains — tinder_api.py is a set of well-named capabilities with explicit confirmation parameters — but MCP is now an implementation detail. Users never see servers, transports, or tool schemas; they see a dashboard.

AI / LLM architecture

One AI provider: Google Cloud Gemini via Vertex AI (model selectable with GEMINI_MODEL). Authentication uses GCP application credentials — on Cloud Run the built-in service account, locally your gcloud login. An AI Studio API key (GEMINI_API_KEY) is supported as a fallback for machines without gcloud. All model output is validated against Pydantic schemas before it reaches the UI.

Authentication architecture

Token → in-memory session (never persisted) → HttpOnly cookie referencing the session. Disconnect deletes it; 2h idle expiry; masked fingerprint display. Live mode is localhost-only — the deployed demo instance refuses live connections because datacenter IPs get accounts flagged.

Security

  • Token is stored only in process memory; never in files, DBs, logs, or analytics
  • Tokens are scrubbed from all error messages and logs
  • All writes require confirm: true from an explicit user action
  • The AI module cannot import the Tinder layer — it can draft, never act
  • .env is gitignored; no credentials are committed
  • Disconnect drops access instantly; Tinder logout invalidates the token everywhere

Troubleshooting

“That doesn't look like a Tinder token”

You likely copied the row name instead of the value, or missed characters. The full value is 36 characters including dashes. Re-copy with double-click + Ctrl/⌘+C — see the guide.

“Your Tinder connection has expired”

The token stopped working (Tinder ended the session — normal after logout or long gaps). Log into tinder.com again and paste a fresh token.

“Tinder has your account in a verification state”

New accounts sit behind a selfie/photo review. Complete it in the Tinder mobile app; profile tools keep working meanwhile, match tools unlock after review.

“Tinder is asking us to slow down”

Rate limit hit — wait a minute. Wingman already throttles to one Tinder call at a time.

“The AI service is busy”

Gemini hiccup. Retry — the app automatically backs off and retries transient model errors once.

Live connection refused on the hosted demo

By design. The public instance is demo-only; run Wingman locally for live access (protects your account from datacenter-IP flags).

FAQ

Is this affiliated with Tinder?

No. Wingman is an independent personal-assistant project that works with your own account, and encourages use within Tinder's terms.

Does the AI learn from my data?

Your profile/conversation JSON is sent to Gemini per request to produce the analysis. Nothing is stored by Wingman beyond your session.

Can I self-host?

Yes — it's on GitHub. Clone, pip install -r requirements.txt, python app.py. You'll need gcloud logged in (or a Gemini API key) for the AI.

Why is swiping not available?

We only enable verified capabilities. Swipe endpoints are documented and implemented but not exposed until reliability and account-safety checks pass. Check the research log for the current status.
